Stocklël uses **PostgreSQL 15** with **Prisma 5** as the ORM. The schema is defined in `prisma/schema.prisma`. All migrations are tracked in `prisma/migrations/` and applied with `prisma migrate deploy` in production.

## Datasource and generator

```prisma
generator client {
  provider      = "prisma-client-js"
  binaryTargets = ["native", "linux-musl-openssl-3.0.x"]
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```

The `binaryTargets` array ensures the generated client works both on your local machine (`native`) and inside the Alpine-based Docker container (`linux-musl-openssl-3.0.x`).

## Migration approach

- **Development:** `npx prisma migrate dev` — detects schema drift, creates a new migration file, and applies it.
- **Production:** `npx prisma migrate deploy` — applies pending migrations without interactive prompts. This command runs automatically at the end of every GitHub Actions deployment.

<Warning>
  Never run `prisma migrate dev` against a production database. It can prompt for resets and is not designed for automated pipelines.
</Warning>

## Models

### User

Stores all application users. Authentication is custom JWT-based; `sessionVersion` is incremented to invalidate all active sessions for a user at once.

| Field | Type | Notes |
|---|---|---|
| `id` | `String` (UUID) | Primary key |
| `email` | `String` | Unique |
| `password` | `String` | bcrypt hash |
| `name` | `String?` | Display name |
| `tienda` | `String` | Assigned store, defaults to `"CEDIS"` |
| `rol` | `String` | `"usuario"` or `"admin"`, defaults to `"usuario"` |
| `paginasPermitidas` | `String[]` | Array of page-permission slugs |
| `sessionVersion` | `Int` | Increment to invalidate all sessions |
| `emailVerified` | `DateTime?` | Set when the user verifies their email |
| `verificationToken` | `String?` | One-time email verification token |
| `verificationTokenExpiry` | `DateTime?` | Expiry of the verification token |
| `resetToken` | `String?` | One-time password reset token |
| `resetTokenExpiry` | `DateTime?` | Expiry of the reset token |
| `createdAt` / `updatedAt` | `DateTime` | Audit timestamps |

**Relations:** has many `Venta`, `OrdenCompra`, `Recepcion`, `Paquete` (created and approved), `AsignacionInventario`, `PagoOrdenCompra`, `VentaEnPapelera`, and `ProductoEnTienda`.

### Producto

The product catalogue. Each product can have multiple cost records, appear in multiple stores, and be included in purchase orders, packages, and sales.

| Field | Type | Notes |
|---|---|---|
| `id` | `Int` | Auto-increment primary key |
| `clave` | `String` | Unique internal product code |
| `grupo` | `String?` | Product group/family |
| `proveedor` | `String?` | Legacy supplier name (prefer the `Proveedor` relation) |
| `modelo` | `String?` | Model identifier |
| `categoria` | `String?` | Product category |
| `descripcion` | `String?` | Free-text description |

| `createdAt` | `DateTime` | Creation timestamp |

### Venta

| Field | Type | Notes |
|---|---|---|
| `id` | `Int` | Auto-increment primary key |
| `clave` | `String` | Product code at time of sale |
| `grupo` | `String` | Product group at time of sale |
| `productos` | `String` | Product description string |
| `tipoMovimiento` | `String` | Movement type |

### OrdenCompra

| Field | Type | Notes |
|---|---|---|
| `id` | `Int` | Auto-increment primary key |
| `folio` | `String` | Unique folio, e.g. `OC-2024-001` |

### GestionDano

|---|---|---|

## Enums

### `EstadoOrdenCompra`

Drives the purchase order lifecycle.

| Value | Meaning |
|---|---|
| `BORRADOR` | Order created but not yet sent to the supplier |
| `ENVIADA` | Order sent, awaiting delivery |
| `RECIBIDA_PARCIAL` | At least one partial reception has been registered |
| `RECIBIDA_COMPLETA` | All ordered items have been received |
| `CANCELADA` | Order cancelled |

### `MotivoDano`

Classifies why goods were damaged during the supply chain.

| Value | Meaning |
|---|---|
| `DANO_EN_TRASLADO` | Damaged during transit |
| `DANO_EN_DESCARGA` | Damaged during unloading |
| `DANO_EN_MANIOBRA` | Damaged during handling |
| `DANO_EN_ALMACEN` | Damaged in the warehouse |

### `DecisionDano`

Records the action decided for a damaged item.

| Value | Meaning |
|---|---|
| `REPARAR_Y_COBRAR_PROVEEDOR` | Keep the item, repair it, and charge the cost to the supplier in a future order |
| `REPARAR_CULPA_INTERNA` | Keep and repair the item; internal fault — no charge to supplier |
| `DEVOLVER_Y_PEDIR_REPOSICION` | Return the item and request a replacement (used for critical damage) |

### `EstadoCobro`

Tracks whether a damage charge has been applied to a supplier.

| Value | Meaning |
|---|---|
| `PENDIENTE` | Charge pending application |
| `APLICADO` | Charge has been applied to a purchase order |
| `CANCELADO` | Charge cancelled |

### `EstadoDevolucion`

Tracks the lifecycle of a merchandise return.

| Value | Meaning |
|---|---|
| `PENDIENTE_ENVIO` | Return created, not yet sent to supplier |
| `ENVIADA` | Return sent to supplier |
| `REPUESTA` | Supplier has provided the replacement |
| `CANCELADA` | Return cancelled |

### `EstadoPaquete`

Tracks the state of an outlet package.

| Value | Meaning |
|---|---|
| `PENDIENTE` | Package defined but not yet physically assembled |
| `CREADO` | Package assembled; stock deducted from components |
| `RECHAZADO` | Package rejected by the purchasing team |
| `DESARMADO` | Package disassembled; component stock returned |
