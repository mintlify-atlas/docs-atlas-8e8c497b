title: "Deployment"

Stockel ships with a GitHub Actions workflow that automatically deploys every push to the `main` branch to a VPS. The production stack adds nginx as a reverse proxy and Certbot for automatic TLS certificate management via Let's Encrypt.

## Architecture overview

In production, Docker Compose runs four containers:

| Container | Image | Role |
|---|---|---|
| `stockel_app` | Built from `./Dockerfile` | Next.js app on internal port 3000 |
| `stockel_db` | `postgres:15` | PostgreSQL with persistent volume |
| `stockel_nginx` | `nginx:alpine` | Reverse proxy, TLS termination |
| `stockel_certbot` | `certbot/certbot` | Automatic certificate renewal every 12 h |

The `nginx` and `certbot` services use the `prod` Docker Compose profile, so they only start when you pass `--profile prod`.

## CI/CD with GitHub Actions

The workflow file lives at `.github/workflows/deploy.yml`. It triggers on every push to `main` and SSHes into the VPS to run the deployment commands.

```yaml .github/workflows/deploy.yml
name: Deploy to VPS

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: ubuntu-latest

    steps:
      - name: Deploy to VPS
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.VPS_HOST }}
          username: ${{ secrets.VPS_USERNAME }}
          password: ${{ secrets.VPS_PASSWORD }}
          script: |
            cd /root/stockel
            git pull origin main
            docker compose down
            docker compose --profile prod up -d --build
            docker compose exec -T app npx prisma migrate deploy
            echo "Deploy completado exitosamente!"
```

### Required GitHub secrets

Configure these in your repository under **Settings → Secrets and variables → Actions**:

| Secret | Description |
|---|---|
| `VPS_HOST` | IP address or hostname of your VPS |
| `VPS_USERNAME` | SSH user (e.g. `root`) |
| `VPS_PASSWORD` | SSH password for that user |

<Note>
  The workflow uses password-based SSH via `appleboy/ssh-action`. For improved security, replace the password with an SSH private key using the `key` field instead.
</Note>

## Environment variables for production

Create a `.env` file on the VPS at `/root/stockel/.env`. These values are read by Docker Compose at runtime:

```env .env
# Database — hostname is "db" (Docker internal network)
DATABASE_URL=postgresql://stockel_user:StockelSecurePass2024@db:5432/stockel_db

POSTGRES_USER=stockel_user
POSTGRES_PASSWORD=StockelSecurePass2024
POSTGRES_DB=stockel_db

# JWT secret — generate a strong random value
JWT_SECRET=replace-with-a-strong-random-secret

# App URL — your production domain
NEXT_PUBLIC_APP_URL=https://cbros.space

# Google reCAPTCHA
NEXT_PUBLIC_RECAPTCHA_SITE_KEY=your-production-site-key
RECAPTCHA_SECRET_KEY=your-production-secret-key

# SMTP
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=you@example.com
SMTP_PASS=your-smtp-password
EMAIL_FROM=no-reply@cbros.space

# OpenAI
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o
```

<Warning>
  Do not use the default PostgreSQL password shown in `docker-compose.yml` (`StockelSecurePass2024`). Generate a unique, strong password for your production database and update both `POSTGRES_PASSWORD` and the password segment of `DATABASE_URL`.
</Warning>

## Deployment steps

<Steps>
  <Step title="Provision the VPS">
    Stockël is tested on Ubuntu 24.04 LTS. Install the required dependencies on your server:

    ```bash
    # Install Docker
    curl -fsSL https://get.docker.com | sh

    # Install Docker Compose plugin
    apt-get install -y docker-compose-plugin
    ```
  </Step>

  <Step title="Clone the repository on the VPS">
    ```bash
    ssh root@your-vps-ip
    cd /root
    git clone https://github.com/ChrisOmar43/stockel.git
    cd stockel
    ```
  </Step>

  <Step title="Create the .env file">
    Create `/root/stockel/.env` with the production values from the section above.

    ```bash
    nano /root/stockel/.env
    ```
  </Step>

  <Step title="Configure nginx and TLS">
    The nginx configuration is at `nginx/nginx.conf`. It redirects HTTP to HTTPS and proxies all traffic to the `app` container:

    ```nginx nginx/nginx.conf
    events {
        worker_connections 1024;
    }

    http {
        upstream app {
            server app:3000;
        }

        # Redirect HTTP to HTTPS
        server {
            listen 80;
            server_name cbros.space www.cbros.space;

            location /.well-known/acme-challenge/ {
                root /var/www/certbot;
            }

            location / {
                return 301 https://$host$request_uri;
            }
        }

        # HTTPS with TLS 1.2 / 1.3
        server {
            listen 443 ssl;
            http2 on;
            server_name cbros.space www.cbros.space;

            ssl_certificate /etc/letsencrypt/live/cbros.space/fullchain.pem;
            ssl_certificate_key /etc/letsencrypt/live/cbros.space/privkey.pem;

            ssl_protocols TLSv1.2 TLSv1.3;
            ssl_prefer_server_ciphers off;

            client_max_body_size 100M;

            location / {
                proxy_pass http://app;
                proxy_http_version 1.1;
                proxy_set_header Upgrade $http_upgrade;
                proxy_set_header Connection 'upgrade';
                proxy_set_header Host $host;
                proxy_cache_bypass $http_upgrade;
                proxy_set_header X-Real-IP $remote_addr;
                proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
                proxy_set_header X-Forwarded-Proto $scheme;
            }
        }
    }
    ```

    Update `server_name` in `nginx/nginx.conf` to match your own domain before the first deploy.
  </Step>

  <Step title="Start the production stack">
    ```bash
    docker compose --profile prod up -d --build
    ```

    This starts all four containers: `stockel_app`, `stockel_db`, `stockel_nginx`, and `stockel_certbot`.
  </Step>

  <Step title="Run migrations">
    ```bash
    docker compose exec -T app npx prisma migrate deploy
    ```

    Use `migrate deploy` (not `migrate dev`) in production. It applies pending migrations without prompting for confirmation or resetting the database.
  </Step>

  <Step title="Configure GitHub secrets and push">
    Add `VPS_HOST`, `VPS_USERNAME`, and `VPS_PASSWORD` to your GitHub repository secrets. From this point on, every push to `main` triggers an automatic deploy — no manual SSH required.
  </Step>
</Steps>

## Manual deploy

Use this when you need to deploy outside of the automated pipeline, for example after editing the `.env` file directly on the server.

```bash
# Connect to the VPS
ssh root@your-vps-ip

# Go to the project directory
cd /root/stockel

# Pull the latest code
git pull origin main

# Rebuild and restart all containers
docker compose down
docker compose --profile prod up -d --build

# Apply any new migrations
docker compose exec -T app npx prisma migrate deploy
```

<Tip>
  After a deploy, follow the app logs for 30 seconds to confirm it started cleanly:

  ```bash
  docker compose logs app -f
  ```
</Tip>
